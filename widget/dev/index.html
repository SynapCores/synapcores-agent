Sprint 2 — gateway direct

@synapcores/widget — talking to the SynapCores gateway

No mock backend. This page connects directly to a real SynapCores instance at http://localhost:8080 using the gateway's existing /ws endpoint and the AiChatWsMessage protocol. The agent loop is AGENT_RUN() in-DB — recall memory + RAG + tool routing + grounded generation, all native, no Python middleware.

Set up first: see RUN_AGAINST_SYNAPCORES.md for the one-time setup — run a SynapCores container, obtain a JWT, then paste it into the data-token attribute in the <script> tag at the bottom of this file. Production embedders won't need this step once Sprint 2 Phase B ships the POST /v1/widget/token endpoint.

What this widget exercises in the engine

  • send_message → gateway → chat_engine → AGENT_RUN in-DB
  • Streaming message_chunk frames → live token render
  • message_complete → final markdown render
  • JWT auth on /ws?token=…
  • Per-session memory keyed by session_id (UUID generated on widget mount)

Run the dev server

cd widget
npm install
npm run build    # writes dist/widget.js
npm run dev      # esbuild watch + http.server serving widget/ at :5050

Open http://localhost:5050/dev/.

The <script> below is the entire install for production embedders, plus a data-token for dev use (replace REPLACE_WITH_JWT with the JWT printed by the curl command in RUN_AGAINST_SYNAPCORES.md).
